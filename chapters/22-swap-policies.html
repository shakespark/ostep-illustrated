这一章要解决什么

如何决定踢出哪个页？操作系统如何决定从内存中踢出哪一页（或哪几页）？这个决定由系统的替换策略（replacement policy）做出，它通常遵循一些通用原则，同时也包含一些调整来避免极端情况下的糟糕表现。

How can the OS decide which page (or pages) to evict from memory?

上一章（第 21 章）搭好了机制：present 位、页错误、交换空间。机制只回答"怎么把页换进换出"，却没回答最要命的问题：内存满了，该牺牲谁？选错了，程序会以磁盘速度（比内存慢上万倍）运行。

本章把物理内存看成"虚拟页的缓存"，依次研究最优策略 OPT（作为标尺）、FIFO、Random、LRU，再看工作负载如何决定策略优劣、LRU 如何用 use 位和时钟算法近似实现、脏页如何影响决策，最后讨论内存彻底不够时的抖动（thrashing）。下一章（第 23 章）会看到 VAX/VMS 和 Linux 在真实系统里如何落地这些思想。

核心概念速览

内存是页的缓存

目标：让缓存未命中（cache miss）尽量少，也就是少从磁盘取页。

AMAT

平均内存访问时间 = TM + PMiss·TD。磁盘太慢，哪怕 0.1% 的未命中率也会主导总时间。

最优策略 OPT / MIN

踢出"将来最晚才被访问"的页。要预知未来，无法实现，但是绝佳的比较标尺。

FIFO 与 Random

实现简单，但不区分页的重要程度；FIFO 还会出现 Belady 异常。

LRU

踢出最近最少使用的页，依据局部性原理（principle of locality）用历史预测未来。

use 位 + 时钟算法

完美 LRU 太贵；硬件置 use 位、OS 用"转圈的指针"清位找 0，近似 LRU。

脏页（dirty page）

被修改过的页踢出前必须写回磁盘，代价更高；很多系统优先踢干净页。

抖动（thrashing）

进程们的工作集之和超过物理内存，系统一直在换页。对策：准入控制或 OOM killer。

内存是页的缓存：用 AMAT 衡量

主存只能装下系统所有页的一个子集，所以它就是虚拟内存页的缓存。替换策略的目标是最小化缓存未命中次数（等价地，最大化命中次数）。有了命中与未命中，就可以计算平均内存访问时间（Average Memory Access Time，AMAT）：

AMAT = TM + (PMiss · TD)

TM：访问内存的代价；TD：访问磁盘的代价；PMiss：未命中概率（0.0～1.0）。注意内存访问的代价总要付，未命中时再额外付一次磁盘代价。

原书的例子：4KB 地址空间、256 字节页（4 位 VPN + 8 位偏移），进程依次访问 0x000, 0x100, …, 0x900（前 10 个页各一次），除了 VPN 3 以外的页都已在内存。于是得到"命中、命中、命中、未命中、命中×6"，命中率 90%，PMiss = 0.1。取 TM = 100ns、TD = 10ms：AMAT = 100ns + 0.1·10ms ≈ 1.0001 ms，大约 1 毫秒；若命中率为 99.9%，AMAT 变成 10.1 µs，快了约 100 倍。自己拖一拖滑块感受一下：

最优替换策略（OPT / MIN）

Belady 很早就证明：踢出将来最晚才会被访问的那个页，得到的未命中次数最少。直觉很简单——既然必须扔掉一个，就扔掉"离下次被需要最远"的那个；其他页都会比它先被用到，所以都比它重要。

原书用的访问序列是 0, 1, 2, 0, 1, 3, 0, 3, 1, 2, 1，缓存能放 3 页。前 3 次访问是冷启动未命中（cold-start / compulsory miss）；随后 0、1 命中；访问 3 时缓存已满，必须替换。OPT 往未来看：

结果（原书 Figure 22.1）：6 次命中、5 次未命中，命中率 6/11 = 54.5%；如果不计冷启动未命中（每个页的第一次访问），命中率是 6/7 = 85.7%。第 9 次访问页 2 时，0 和 3 将来都不再被访问，踢谁都行，原书踢了 3。

强制未命中（compulsory miss，又叫冷启动未命中）：缓存一开始是空的，第一次访问某项必然未命中。容量未命中（capacity miss）：缓存装满了，只好踢掉某项才能装新项。冲突未命中（conflict miss）：硬件缓存因组相联（set-associativity）限制了放置位置而产生；OS 的页缓存是全相联的（页可以放进任意页框），所以不存在这一类。

和最优比较很有用。单说"我的新算法命中率 80%"没有意义；说"最优也只有 82%"，就知道已经很接近理想、可以停手了。所以 OPT 虽然无法实现，却是所有模拟研究的标尺。

两个简单策略：FIFO 与 Random

FIFO（先进先出）

页进入内存时排进队列，替换时踢掉最先进入的那个。优点只有一个：实现极其简单。同一序列下 FIFO 只有 4 次命中，命中率 36.4%（不计冷启动 57.1%）。问题出在第 5 次访问：页 0 已经被访问过好几次，FIFO 仍然因为它"来得最早"把它踢掉，紧接着访问 0 就又未命中。FIFO 无法判断页的重要性。

Random（随机）

内存吃紧时随机挑一个踢掉。和 FIFO 一样简单，一样不"聪明"，表现完全取决于运气。原书 Figure 22.3 那一次运气不错，拿到 5 次命中。原书把这个实验重复了 10,000 次（不同随机种子）：略多于 40% 的情况下 Random 和 OPT 一样好（6 次命中），有时却只有 2 次甚至更少。下面在浏览器里现场重做这个实验：

Belady 异常（Belady's Anomaly）

利用历史：LRU

FIFO、Random 的通病是可能踢掉一个马上就要用到的重要页。和调度一章一样，我们再次用过去预测未来。两种历史信息：

  • 频率（frequency）：被访问很多次的页可能有价值 → LFU（Least-Frequently-Used），踢出访问最少的页。
  • 近期性（recency）：越近被访问的页越可能再次被访问 → LRU（Least-Recently-Used），踢出最久没被访问的页。

这类策略都建立在局部性原理（principle of locality）上：程序倾向于反复访问某些代码（如循环）和数据结构（如循环里访问的数组）。

空间局部性（spatial locality）：访问了页 P，很可能接着访问 P−1 或 P+1。时间局部性（temporal locality）：最近访问过的页很可能不久后再次被访问。局部性只是一种经验规律（启发式），并非所有程序都遵守，有些程序的访问几乎是随机的。

在同一序列上，LRU 第一次替换时踢掉 2（0、1 更近被用过），第二次踢掉 0（1、3 更近）。两次决定都正确，结果 6 次命中，与 OPT 持平（原书脚注坦白：这个例子是"特意挑的"）。与之相反的 MFU、MRU 在大多数情况下表现很差，因为它们与局部性背道而驰。

从这三张图可以读出原书的结论：

  1. 无局部性时，LRU、FIFO、Random 表现几乎一样，命中率就等于"缓存大小 / 100"；缓存能装下全部页时，所有策略（包括 Random）都收敛到 100%；OPT 明显更好——偷看未来确实有用。

  3. 循环顺序是 LRU 和 FIFO 的最坏情况：它们总踢掉最老的页，而循环下最老的页恰恰马上要用。缓存 49 页、循环 50 页，命中率竟是 0%！Random 反而好得多——Random 的一个优点就是没有奇怪的极端行为。这类访问在数据库等重要应用中很常见。

LRU 比 Random/FIFO 高出的那几个百分点重要吗？"看情况"：如果每次未命中代价巨大（这很常见），一点点命中率提升也能带来巨大的性能差异。

实现历史算法：LRU 太贵，用 Clock 近似

完美的 LRU 要在每一次内存访问（取指、load、store）时更新数据结构，把该页移到 MRU 端。FIFO 只在装入和淘汰时操作队列，LRU 却要为每次访问记账，没有精心设计就会严重拖慢性能。

一种思路是硬件辅助：每次访问时硬件把当前时间写进该页的"时间字段"，替换时 OS 扫描所有时间字段找最小者。可是 4GB 内存、4KB 页就有 100 万个页，每次替换都扫一百万项，太慢了。

如何实现 LRU 替换策略？既然完美实现 LRU 代价高昂，能否以某种方式近似它，并且仍然获得想要的效果？

Given that it will be expensive to implement perfect LRU, can we approximate it in some way, and still obtain the desired behavior?

答案是可以。需要一点硬件支持：use 位（又叫 reference bit，引用位），最早出现在第一个分页系统 Atlas 上。每个页一个 use 位；页被读或写时，硬件把它置 1；硬件从不清零，清零是 OS 的事。

时钟算法（clock algorithm，Corbató 提出）：把所有页排成一个环，一根"表针"指向某一页。需要替换时：

  1. 看表针指向的页 P：若 use = 1，说明 P 最近被用过，不是好的牺牲者 → 把 use 清 0，表针前进到 P+1；
  2. 重复，直到遇到 use = 0 的页，把它踢掉（最坏情况下转一整圈，把所有位都清掉后回到起点）。

这不是唯一的做法：任何"定期清 use 位、然后区分 1 和 0 来决定踢谁"的方案都可以。Clock 的好处是不需要反复扫描全部内存。原书 Figure 22.9 里的 Clock 变体是"随机挑页扫描"，遇到 use=1 就清零，遇到 use=0 就选它；它不如完美 LRU，但比完全不看历史的策略好——上面曲线图里的 Clock 线正是如此。

考虑脏页

Corbató 也提出了对时钟算法的一个常见改进：考虑页在内存中是否被修改过。被修改过的页叫脏页（dirty page），踢出前必须写回磁盘，代价高；没修改过的干净页（clean page）可以直接重用页框，不需要额外 I/O。硬件为此提供修改位（modified bit，又叫 dirty bit），页被写时置 1。

于是时钟算法可以改成：先找既没被使用又干净的页踢；找不到，再找没被使用但脏的页；以此类推。在上面的模拟器里勾选"Clock 优先踢干净页"、载入"带写操作"预设，对比写回次数（本站的实现：第一圈只找 (use=0, 干净) 且不清位；找不到就第二圈找 (use=0, 脏)，途中把 use=1 清零；再不行重复）。

其他虚拟内存策略

替换不是 VM 子系统唯一的策略：

  • 页选择策略（page selection policy，Denning 的叫法）：何时把页调入内存？大多数页用按需分页（demand paging）——被访问时才调入。OS 也可以猜测某页即将被用到而提前调入，这叫预取（prefetching），只有在成功概率较大时才值得做。例如代码页 P 被调入时，很可能 P+1 也快要用到，一起调入。
  • 写出策略：可以一页一页地写回，但很多系统会在内存里攒一批待写页，一次性写到磁盘，这叫聚集（clustering）或分组写（grouping）。磁盘做一次大写比很多次小写高效得多。

抖动与准入控制

最后一个问题：如果内存被超额订阅（oversubscribed），正在运行的进程们的内存需求之和超过了物理内存，怎么办？系统会不停地换页，这种状况叫抖动（thrashing）。

早期一些系统有相当复杂的机制来检测和应对抖动。例如给定一组进程，系统可以决定暂时不运行其中一部分，希望剩下进程的工作集（working set，正在活跃使用的页）能装进内存，从而取得进展。这叫准入控制（admission control）：有时候把少量工作做好，胜过把所有工作一起做砸。

一些现代系统的做法更"粗暴"：某些版本的 Linux 在内存超额时运行OOM killer（out-of-memory killer），挑一个吃内存的进程杀掉。它确实能缓解内存压力，但如果杀掉的是 X server，所有需要显示的应用都会无法使用。

缓存 49 页时 LRU 和 FIFO 都是 0%（每次都恰好踢掉下一个要用的页），Random 却很高（本站种子下约 95%），因为它不会系统性地踢错。缓存到 50 页时，所有策略都只剩 50 次冷启动未命中，命中率 99.5%。
在抖动模拟器中，M=64、W=16。预测吞吐量从哪个 n 开始断崖式下降？勾选准入控制后又会怎样？
看答案
⌊64/16⌋ = 4 个进程的工作集恰好能装下，n ≤ 4 时吞吐量接近 1；n = 5 时工作集总和 80 > 64，全局 LRU 下每个进程轮到自己时，它的页往往已被别人挤出去，吞吐量骤降——这就是抖动。启用准入控制后，同时只运行 4 个，其余排队，吞吐量保持在高位。

自测题

TM=100ns、TD=10ms，命中率 99.9% 时 AMAT 约为？
AMAT = 100ns + 0.001 × 10ms = 100ns + 10µs = 10.1µs。即使只有千分之一的未命中，时间也比纯内存访问慢约 100 倍。
OPT 策略在需要替换时踢出哪个页？
OPT（Belady 的 MIN）看的是未来：踢掉"下次使用最远"的页。C 是 LRU，B 是 FIFO，A 是 LFU。
为什么 OS 的页缓存不存在"冲突未命中（conflict miss）"？
冲突未命中源自硬件缓存的组相联限制（某项只能放在特定几个位置）。OS 管理物理内存时，任何页可以放进任何空闲页框，所以只有强制未命中和容量未命中。
关于 Belady 异常，下列说法正确的是？
具备栈特性的算法（如 LRU、OPT）中，大小为 N+1 的缓存总包含大小为 N 的缓存内容，因此不会异常。FIFO、Random 没有栈特性。
在"循环访问 50 个页"的负载下，缓存有 49 页。LRU 的命中率大约是？
LRU 总是踢掉最久没用过的页，而循环中它恰好是下一个要访问的页，于是每次都未命中。这是 LRU/FIFO 的最坏情况，Random 反而表现好得多。
关于 use 位（引用位），哪项正确？
硬件只负责"置 1"，OS（例如时钟算法扫描时）负责清零。脏页由另一个位——修改位（dirty bit）——表示。
时钟算法扫描时遇到 use=1 的页，会怎么做？
use=1 说明它最近被用过，给它"第二次机会"：清零并跳过。若在表针转回来之前它又被访问，use 会再次被置 1。
系统发生抖动（thrashing）时，下列哪种做法对应原书说的"准入控制"？
准入控制是"少做一些，但做好"：挑出一个子集运行。B 是 Linux OOM killer 的做法，更粗暴。抖动的根源是内存超额订阅，再好的替换算法也救不了（A 错）。

常见误区与小结

  • "缓存越大命中率一定越高"——对 FIFO、Random 不成立（Belady 异常）；只有具备栈特性的策略才有这种单调性。
  • "LRU 总是最好的现实策略"——在循环顺序负载下 LRU 是最差的之一，Random 反而更稳；现代算法（如 ARC）强调"抗扫描（scan resistance）"。
  • "OPT 能实现，只是开销大"——OPT 需要预知未来的访问序列，通用 OS 根本无法实现；它只用于离线比较。
  • "命中率 90% 已经很好了"——对页缓存而言，10% 的未命中就会让 AMAT 变成约 1ms，比内存慢一万倍。
  • 把 use 位和 dirty 位混为一谈——use 位记录"最近是否被访问"（读或写），dirty 位记录"是否被写过"。
  • 物理内存是虚拟页的缓存；目标是最小化未命中，用 AMAT = TM + PMiss·TD 衡量，磁盘代价让未命中率极其敏感。
  • OPT 踢"最晚再用"的页，是无法实现的最优标尺；原书序列上 OPT 6/11 = 54.5%，FIFO 4/11 = 36.4%，Random（原书那次）5/11，LRU 6/11。
  • FIFO/Random 简单但不看重要性；LRU 利用局部性，但完美实现太贵；use 位 + 时钟算法是实用的近似，考虑 dirty 位还能少写回。
  • 策略好坏取决于工作负载：无局部性时都差不多，80-20 时 LRU 占优，循环顺序时 LRU/FIFO 崩溃而 Random 稳健。
  • 其他策略：按需分页 vs 预取；写回时聚集。内存超额订阅时出现抖动，应对方式有准入控制和 OOM killer。
  • SSD 等快速存储改变了内存与存储的速度比，替换算法正在迎来复兴。下一章看这些思想在 VAX/VMS 与 Linux 中的真实形态：分段 FIFO + 二次机会链表、Linux 的 2Q（active/inactive 链表）。
